# Lab6 打地鼠操作手册（EGO1）

本手册用于独立附加题工程的仿真、下载和验收。基础题另用 lab6/code 工程。下文的板上显示均为预期现象，实际结果须上板记录；本地仿真通过不代表已经完成实物验收。

## 1. 文件与硬件准备

使用 EGO1，Vivado 器件选择 xc7a35tcsg324-1。准备支持数据传输的 USB 线和串口软件。本游戏不需要矩阵键盘，不需要外接蜂鸣器。代码和管脚约束在相邻的 src 目录，设计原理见 design.md。

| 操作或信号 | 对应硬件 |
| --- | --- |
| 复位 | S0 / R11，按下为高电平 |
| 开始或重新开始 | S2 / R15，稳定按下 20 ms |
| 静音 | DIP0 / T5，上拨为 1 |
| 反馈灯 | LD1_0 / K3，高电平亮 |
| FPGA 串口接收 | N5 |
| 系统时钟 | P17，100 MHz |

注意：附加题按课程游戏页面用 S0 复位，基础题用 S1；不是同一个按键。DIP0 是小型 DIP 开关组第 0 位，不是大拨码开关 SW0。LD1_0 对应手册中的 D1_0 / LED1_0，不是 LD2_0。

## 2. 建立 Vivado 工程

1. 新建 RTL Project，选择 xc7a35tcsg324-1，将工程保存在源代码目录外，避免把整个 Vivado 工程纳入提交。
2. Add Design Sources 加入 top.v、key_press.v、uart_recv.v、lfsr.v、game_control.v、game_display.v、segment_scan.v、effect_led.v，共八个文件，设计顶层设为 top。
3. Add Constraints 加入本目录 src 中的 pin.xdc。确认 rst 为 R11、uart_rx 为 N5，保留 create_clock 的 10 ns 时钟约束。
4. Add Simulation Sources 只加入 top_tb.v，将仿真顶层设为 top_tb。不要将测试文件加入综合，不要加入 render_manual.py，不要混入基础题的同名模块或约束。
5. 保持硬件默认参数：CLK_HZ=100000000、BIT_CYCLES=10416、DEBOUNCE_CYCLES=2000000、SCAN_CYCLES=100000。

UART 默认采用 9600 baud、8 数据位、无校验、1 停止位、无流控。每位实际为 104.16 微秒，帧长约 1.0416 ms。本独立游戏只接收，不回传文本；电脑接收区没有回复是正常行为。

## 3. 运行与观察仿真

启动 Run Behavioral Simulation，在 /top_tb/dut 中加入 current_state、start_press、recv_valid、recv_data、score、time_left、mole、hit、miss、effect_led、led_en、led_cx、led_cx1；另加入 /top_tb 下的 rst、button_s2、mute、uart_rx。进入 u_game_control 加入 next_state、second_count，可观察三段式状态机。

score 与 time_left 设 Hex，按 BCD 阅读；例如 20 表示二十秒，不要设普通十进制而误读为 32。recv_data 可设 ASCII，mole 设 Unsigned Decimal。current_state 与 next_state 的编码为 0 待机、1 游戏、2 结束。

1. Run All，仿真应在约 233.67 微秒结束。先看复位后的待机：分数 00、时间 20、洞位 0。
2. 观察 S2 的短抖动未开始；随后稳定长按只产生一次 start_press，游戏开始后时间正常递减。
3. 观察第一帧发送当前洞位，hit 仅一拍，分数变 01；第二帧故意发送错误数字，miss 仅一拍，洞位和分数保持。
4. 第三帧为回车，应忽略。mute 为高后反馈灯关闭，时间仍递减；取消静音后恢复当前有效反馈。
5. 游戏结束后 time_left 为 00、mole 为 0，收到数字不再计分；结束反馈到期后灯灭。
6. S2 再次开始应清零分数并恢复 20；最后复位回到待机。

本 testbench 没有自动评分，结束本身不等于通过。需结合上述波形观察；另行运行的本地自检结果见 verification.md。需要报告材料时保存原始波形截图，标注信号、时间尺度和预期对应关系。

仿真参数缩短为 CLK_HZ=1000、BIT_CYCLES=16、DEBOUNCE_CYCLES=4、SCAN_CYCLES=4，时钟仍为 10 ns。仿真一“秒”为 10 微秒，一局为 200 微秒，位宽为 160 ns。它验证功能顺序，不证明实物 20 秒或 20 ms 消抖。若需要真实时序截图，应另建使用默认参数和足够长等待时间的测试，不能只恢复参数而保留短激励。

## 4. 综合实现与下载

1. 执行 Vivado Run Linter，处理 RESET、CLOCK 以及其他需要修正的告警；保留实际结果，不将 Icarus 编译当成 Vivado Lint。
2. Open Elaborated Design，查看顶层七个子模块连接；在 u_game_control 内核对状态寄存器、次态逻辑与时序输出，保存所需 RTL 图。
3. Run Synthesis 和 Run Implementation，检查错误、关键告警、DRC、Timing Summary，以及 100 MHz 时钟约束是否生效。确认无遗漏端口和冲突管脚。
4. Generate Bitstream，连接 EGO1，Hardware Manager 中 Open Target、Auto Connect，再 Program Device 下载本工程 bitstream。
5. 下载后先按 S0 再松开初始化。源码或约束修改后须重新综合、实现、生成并下载，核对 bitstream 的版本和时间。

设计源码不使用 initial 初始化，不保证用户按复位之前的上电显示。运行期间任何时刻按 S0 都会中止当前游戏、清零数据并回到待机；按住复位时所有数码管和反馈灯关闭。

## 5. 串口与游戏操作

连接 EGO1 的 USB-UART/JTAG 接口，选择实际串口，设置 9600 / 8N1 / 无流控。使用 STR 或文本发送模式，关闭循环发送、自动回车换行和本地回显。建议启用串口软件的按键即时发送；不支持时在发送框输入一个数字，再点击发送。

例如 DK0 显示 3，发送字符“3”，对应字节 0x33；如果使用 HEX 模式，应输入 33，不能输入 03。只接受字符 1 至 8，0、9、字母、回车和换行不触发击打。

| 数码管 | 内容 |
| --- | --- |
| DK7-DK6 | 两位分数，00 至 99 |
| DK5-DK4 | 剩余秒数，20 至 00 |
| DK3-DK1 | 完全关闭 |
| DK0 | 游戏时显示洞位 1 至 8，其他状态关闭 |

按 S2 开局，看到洞位后发送对应数字。命中加一分并立即重新采样洞位；新洞位可以和旧洞位相同，不能单凭数字没变判断未命中。错误数字不换洞位。电脑键盘长按可能自动重复发送，每个字节都是一次独立击打，演示时宜单次点击。

游戏满 20 秒后停止计分，显示最终分数和 00 秒，洞位关闭。结束提示持续三秒，但不用等提示结束就可按 S2 开新局。游戏中按 S2 不暂停、不重新开始；长按跨过结束不会自动开局，必须稳定松开后再按。99 分后保持 99，仍可继续击打。恰好在截止处理沿收到的数字不计分。

## 6. 反馈与静音验收

| 状态或事件 | LD1_0 预期表现 |
| --- | --- |
| 待机 | 1 Hz 持续闪烁 |
| 游戏背景 | 2 Hz 持续闪烁 |
| 命中 | 8 Hz，持续 0.5 秒 |
| 错误数字 | 4 Hz，持续 0.5 秒 |
| 游戏结束 | 约 3 Hz，持续 3 秒，然后熄灭 |

命中和错误反馈覆盖游戏背景，新事件重新计时，结束优先覆盖所有击打反馈。DIP0 上拨时反馈灯关闭，数码管和游戏继续；反馈事件也照常计时，因此取消静音不重放已经到期的提示。可在待机、游戏、结束三个状态分别测试静音。

## 7. 上板逐项记录

以下为验收步骤，不是已完成的实测结论。逐项记录实际现象，异常时保存输入、照片或视频和当时源码版本。

1. S0 复位后分数 00、时间 20、洞位关闭，待机灯闪烁；按住复位时显示关闭。
2. 按 S2 一次开局，用计时器确认约 20 秒结束；长按开始键不重复清零或自动重开。
3. 正确输入一次加一，错误输入不加分不换洞位；输入回车、0、9、字母不影响分数。
4. 命中跨过 09 时显示 10；若需要验证 99 饱和，可配合仿真检查，不把未实际达到的实物分数写成已测。
5. 结束后发送数字不计分，洞位关闭、反馈三秒后停止；重新开始清零分数与计时。
6. 待机、游戏、结束分别测试 DIP0 静音，观察数码管不暂停；游戏中按 S0，确认立即停止并回到待机。
7. 保存实际仿真图、RTL 图、Lint、时序及 DRC 结果和上板照片或视频；附加题只有一次检查机会，应能解释状态机、UART、计时、BCD 和 LFSR。

## 8. 排错与提交

没有反应时先核对已下载正确工程、按过 S0、串口号和波特率，以及文本模式。反馈灯不亮时检查 DIP0 是否上拨、是否已经结束超过三秒，并确认观察的是 LD1_0。数码管异常时检查两组段选与位选均高有效，不能混用 Minisys 约束。

无法在电脑接收区看到游戏回复不是故障：本工程没有发送通道。需要演示组别与学号发送时切换到基础题工程，重新下载其 bitstream；两项可以分别检查。

提交时附加题源码与必做题分目录，按课程平台要求附最终报告。保留 .v 源文件及 pin.xdc，测试文件标注清楚，不提交整个 Vivado 工程、缓存或临时仿真产物。报告只写真实完成的检查和实测；本操作手册不能替代实验报告。
