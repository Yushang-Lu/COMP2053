## 2. 设计材料：框图、状态图、代码截图

### 第二步：绘制电子硬件框图（材料 01）

用 draw.io 等工具按 top.v 手工绘制，不得拿 RTL 截图代替。至少 3 个子模块；当前应画 6 个功能子模块，top 仅作外框，不计作独立子模块。标清模块名、信号名、方向、位宽，并为每个模块写功能与拆分理由。

- 接收链：uart_rx[1] → uart_recv；recv_data[8]、recv_valid[1] → receive_display；recv_digits[24]、recv_enable[6] → segment_scan。
- 发送链：button_s2[1] → key_press；send_press[1] → message_sender；send_data[8]、send_valid[1] → uart_send；uart_tx[1] 输出到电脑。
- 反馈：uart_send 的 send_done[1] → message_sender；其 send_count[8] 是两位 BCD，送往扫描模块。
- 扫描输入：display[32]={send_count,recv_digits}；digit_enable[8]={2'b11,recv_enable}。输出 led_en[8]、led_cx[8]、led_cx1[8]，对应 EGO1 两组独立段选。
- clk、rst 分配给各子模块。方括号内数字在本清单表示“位宽”，画图时可写 /8，或写成 [7:0]，不要误画成索引 [8]。

### 第三步：绘制接收状态转移图（材料 02）

依据 uart_recv.v 画 IDLE、START、DATA、STOP 四态，编码分别为 00、01、10、11。标出复位到 IDLE、各状态自环及以下条件，不只画无条件的四态循环。

- IDLE：din_sync1=0 时进入 START。
- START：cnt_half 且 din_sync1=1 时返回 IDLE（假起始位）；否则 cnt_end 时进入 DATA。
- DATA：cnt_end 且 bit_index=7 时进入 STOP；每个数据位在 cnt_half 时写入 data_reg[bit_index]，低位先接收。
- STOP：cnt_end 时返回 IDLE；cnt_half 且 din_sync1=1 时更新 data 并输出一个时钟周期的 valid。停止位为低时不输出有效数据，但仍按位结束条件返回 IDLE。
- cnt_half 对应 bit_count=5207；cnt_end 对应 10415。输出有效与退出 STOP 不是同一时刻，图、代码和波形分析必须一致。

### 第四步：取得代码截图（材料 03a–03d）

- 03a：uart_recv.v 完整模块代码，可分多张连续截图，包含同步器、三段式状态机、计数、采样、data/valid 输出，不得漏尾部代码。
- 03b：receive_display 的移位与 digit_enable 更新，以及 segment_scan 的位使能门控。说明不足六位时真正关闭数码管，而不是补显示 0。
- 03c：receive_display 的 ASCII 分类转换和 accepted 条件，配合 segment_scan 的段码表。说明 0–9、A–F、a–f 的对应关系，其他字符不更新、不挤掉旧字符。
- 03d：message_sender 的 done 计数代码。说明每发完一个字符才计数，个位逢 9 进位、99 回到 00；不是按一次 S2 只加 1。
- 报告按模板“先贴代码截图，再说明”。其他模块也要说明职责；截图保留清晰字号，不以提交源文件代替截图。

## 3. 接收仿真：通过记录与完整帧

### 第五步：运行官方接收测试

1. 在 Simulation Sources 将 uart_recv_tb 设为顶层，启动 Run Behavioral Simulation。
2. 在 Scope 找到 /uart_recv_tb/u_uart_recv，把内部信号加入 Wave。优先顺序：clk、rst、din、din_sync1、next_state、current_state、bit_count、bit_index、data_reg、data、valid。必须让次态 next_state 在上、现态 current_state 在下。
3. 添加信号后 Restart，再 Run All，避免新增信号没有历史数据。默认只运行 1000 ns 不够；一帧约 1.0416 ms，十组测试约需 10 ms。让 testbench 自行结束。
4. 截取 Tcl Console：十组用例均 success，末尾出现“All test cases passed.”，没有 Timeout 或 failed。保留上下文，不只截最后一行。（材料 04）
5. 若失败，先核对仿真顶层、实际加入的 uart_recv.v、10416 位周期、时钟和复位，不通过修改官方测试的期望值来“通过”。

### 第六步：整理报告波形

1. 选择一帧，例如首帧 0x55，横向覆盖起始位、8 个数据位、停止位及其前后空闲区；data/data_reg 设 Hex，bit_index 可设 Unsigned Decimal，状态设 Binary 或显示自定义状态名。
2. 截图中保留信号全名、时间刻度和数据值；0x55 的串行位顺序应为 1、0、1、0、1、0、1、0。（材料 05a）
3. 在停止位中点附近再局部放大，展示 data 更新和 valid 拉高仅 10 ns，并能看到 clk。（材料 05b）整帧图看不清单拍脉冲时，局部图是补充，不能代替整帧图。
4. 检查次态先组合变化，现态在时钟沿更新；状态顺序和第 2 节状态图一致。din_sync1 比外部 din 有同步延迟，分析时不要把延迟当作错误。
5. 保存波形配置文件及原始截图。写分析时说明起始检测、中点采样、LSB 优先、8 位拼接、停止位校验和单周期有效输出，而不是只写“仿真正确”。

### 本节离开前核对

- 材料 05a 包含完整帧和内部次态/现态；05b 能辨认 valid 的单周期宽度。

## 4. 发送仿真：完整组别与学号

### 第七步：运行整机测试并取发送波形

1. 关闭当前仿真，在 Simulation Sources 将 top_tb 设为顶层，重新启动 Behavioral Simulation。
2. 在 /top_tb/dut 加入 rst、button_s2、send_press、send_valid、send_data、send_done、send_count、uart_tx；另加入 /top_tb/received_byte 和 /top_tb/frames 作为串行解码辅助核对。
3. 将 send_data 和 received_byte 的 Radix 设置为 ASCII。send_count 是 BCD，请用 Hex 读作 00、01、…、09、10、…、13；不能用普通二进制数的十进制显示把 8'h13 误读成 19 个字符。
4. Restart 后 Run All。当前 top_tb 应运行至“All top tests passed: ...”；若出现 fatal 或超时，先定位原因，不以“已结束”代替通过。
5. 缩放到第一次 S2 触发的一整串，展开数据轨道并调宽窗口，保证连续看到“0、5、+、2、0、2、5、3、1、0、5、9、9”。保留 send_valid、uart_tx、send_done 和计数，说明触发、串行输出与计数之间的关系。（材料 06）
6. 相邻两个“9”的 send_data 值可能保持不变，因此用 send_valid 两次脉冲和两帧 uart_tx 辨别，必要时补一张末尾局部图。仅显示 MESSAGE 常量、串口软件文字或一条 uart_tx 位线，都不足以代替功能波形。

### 加速仿真必须如实标注

- top_tb 实际覆盖 BIT_CYCLES=16、CHAR_CYCLES=320、DEBOUNCE_CYCLES=4、SCAN_CYCLES=4；仍是 10 ns 时钟。因此位宽 160 ns、字符起始间隔 3.2 μs，不能称其为 9600 baud 实时波形。
- 实物默认位宽为 104.16 μs，一帧约 1.0416 ms，字符起始间隔 2 ms；13 字符从第一帧开始到最后一帧结束约 25.04 ms，不包含按键消抖等待。
- 本测试可证明字符顺序、完成计数、长按不重复、回绕等逻辑，不用于证明默认 20 ms 消抖时间。若老师要求默认时序截图，应另备使用默认参数的简洁报告 testbench，按下及松开等待超过 20 ms，运行时间覆盖整串；不要直接改加速参数而保留原测试的短超时。
- 当前 top_tb 第一次发送期间也接收字符，随后共发送 8 串、104 帧，最后两位计数为 04，并测试异步复位。波形分析注明本图截取第几次发送；第一次结束应为 13。

## 6. 上板操作：逐项验收与取证

### 第十步：串口连接

连接 EGO1 的 USB-UART/JTAG 接口，选择实际枚举的串口，配置 9600 baud、8 数据位、无校验、1 停止位、无流控，使用 STR/文本模式。关闭自动循环发送与自动追加回车换行。必要时关闭软件本地回显，避免把自己输入的文字当成 FPGA 回传。

FPGA 接收端为 N5、发送端为 T4。硬件手册 UART_RX/T4 指转换芯片接收端，不可因此把 FPGA 的 uart_rx 接 T4。若接收文本被软件分包，可尝试将接收分包超时设为 100 ms；代码本身不发送换行。

### 第十一步：按顺序测试并记录实测

1. 按住 S1：预期所有数码管关闭；松开：DK7–DK6 为 00，DK5–DK0 全空白。若低六位为 000000，未满足“高位不显示”。
2. 电脑发送文本“0”：仅 DK0 显示 0，前五位空白。保存这一步与复位后的对照，证明“空白”不是数字 0。
3. 接着发送“A1b2F”：低六位预期为 0A1b2F。再发送“3”：预期变为 A1b2F3，即第七个有效字符使最旧字符移出。
4. 再发送“G”，或单独发送回车/换行：当前代码预期不改变 A1b2F3。说明大小写 B/D 在七段管上使用 b/d 字形，不要求外观像电脑字体。
5. 清空电脑接收窗口，按一次 S2 后松开：电脑实际收到“05+2025310599”，计数变为 13；保持按下数秒不应重复发送。截图或日志必须来自软件接收区，不是发送输入框。
6. 稳定松开后再次按下：计数变为 26。继续至复位后的第 8 次完整发送，依次核对 13、26、39、52、65、78、91、04；总数为 104，只显示十进制低两位。
7. 再按 S1，确认计数清零、低六位清空，松开后重新收发正常。可补测发送中复位：当前串被中断，不应要求电脑仍收到完整学号。
8. 可补测发送同时接收。当前发送控制器忙时不排队新发送请求，接收通道仍独立工作；不要把这一自定义行为误当作“一次按键必须无限排队”。
