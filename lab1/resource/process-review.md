## 结论

`process.png` 的 mux 主流程和三组上板测试的算术结果正确，报告材料清单也基本齐全；但它不是可以不加修改就照做的完整实验指南。需修正工程名、区分仿真版本、补充译码器练习，并确定实际板型及引脚。

## 两种开发板不能混用约束

### EGO1

- 课程网站的 FPGA 型号为 `xc7a35tcsg324-1`，与手册描述的芯片系列、封装和速度等级相符。
- 手册 PDF 第 7 页（印刷页码 6）：SW0…SW7 分别是 `R1 N4 M4 R2 P2 P3 P4 P5`。
- 同页 DIP 开关的第 0、1 位分别是 `T5`、`T3`，可以用作 en 和 mux_sel，但必须把选择写进操作说明，不能占用已分配给 a、b 的 8 个拨码开关。
- 手册 PDF 第 8 页（印刷页码 7）：LED2_0…LED2_3 分别是 `K2 J2 J3 H4`，与课程网站对 LD2_0…LD2_3 的映射一致。
- 手册明确 LED 高电平点亮，故结果 1111 是四灯全亮，不要在程序里额外取反。

### Minisys：存在待确认的冲突

课程网站型号为 `xc7a100tfgg484-1`。

| 项目 | 课程网站 | 手册 PDF 第 11 页，图 1-2 |
| --- | --- | --- |
| GLD0…GLD3 | `A21 E22 D22 E21` | `J17 L14 L15 L16` |
| `A21 E22 D22 E21` 对应的 LED 组 | GLD0…GLD3 | YLD0…YLD3 |

这不是 Verilog 算法差异，而是硬件资料对 LED 组的标注冲突；可能涉及板卡版本或资料错误，当前材料无法判定具体原因。应查看实际板上 `GLD0` 附近丝印是 `A21` 还是 `J17`，或让实验教师确认。

两份资料中 SW0…SW7 的映射均为 `W4 R4 T4 T5 U5 W6 W5 U6`。手册还给出 SW8=`V5`、SW9=`R6`，可在确认板型后选作额外控制输入。手册和课程网站均说明 LED 高电平点亮。

## VS Code 支持

已检查本机安装目录中的 `mshr-h.veriloghdl-1.29.0/package.json` 和语法配置：

- 已安装 `Verilog-HDL/SystemVerilog` 扩展，注册了 `.v`、`.vh`、`.sv`、`.svh` 和 `.xdc` 等扩展名及相应语法。
- 本实验 `mux.v`、`mux_sim.v` 使用普通 Verilog 后缀即可；`pin.xdc` 是约束文件，不是 Verilog 源码。
- 这里的“支持”指编辑、语法高亮等，不等于自动把 `.v` 渲染成电路图。报告要求的 RTL 图、综合后电路图仍在 Vivado 中生成。
- 本机检测到 Icarus Verilog 13.0，已用于后续本地编译和仿真验证，结果见 [代码说明](../code/README.md)。
- 没有修改 VS Code 全局设置，也没有另装扩展。若编辑器中仍无高亮，需检查该扩展是否被当前工作区禁用。

## 修正后应采用的操作顺序

1. 确认实物板型、器件型号和 LED 引脚，准备相应约束。
2. 先完成官网 3–8 译码器练习并上板验证：禁用全亮；使能 100、输入 000 时第 0 灯灭；输入 001 时第 1 灯灭。
3. 新建名为 `mux` 的工程，加入 `mux.v` 和官方激励的 `mux_sim.v`，分别设置设计/仿真顶层。
4. 运行行为仿真，按上述时间表检查禁用、加法、减法，保存可读的真实波形截图。
5. 打开 Elaborated Design，保存 RTL Schematic。
6. 添加匹配实物的 `pin.xdc`，综合并保存 Synthesized Design 的 Schematic。
7. 实现、生成 bit、连接开发板并下载当前工程的 bit 文件。
8. 验证禁用及输入变化、2+1=3、5−3=2，按教程拍三种情况的照片；记录实际输入与输出，不以预期结果冒充实测。
9. 完成报告、导出并重新检查 PDF，再将官网要求的三个文件打包。

教程主线经以上补正可作为操作清单，但实际完成仍需 Vivado 成功运行、正确的板卡约束及实物验证。网站通用报告要求还提示不要大段照搬 AI 文本；报告分析应基于你自己的真实截图和理解。
